## Technical Notes

Day 11 introduced an analytics layer responsible for collecting destruction metrics during runtime. A new FMVCDDestructionMetrics structure was created to store statistical information generated by the destruction framework.  
  
The destruction manager was extended to own and update the metrics structure. Every processed destruction event now increments the appropriate counters, allowing the framework to measure damage events, destruction state transitions and final object outcomes.  
  
Metrics collection was integrated directly into the destruction event pipeline while remaining independent from the destruction execution logic. After each damage application, the destruction manager evaluates the current destruction state and updates the corresponding statistical counters.  
  
A benchmark reporting function was also implemented to summarise the collected metrics once the automated destruction test finishes. This provides a structured overview of framework behaviour and establishes the first benchmark-oriented reporting capability.  
  
The validated analytics pipeline is:  
  
Destruction Event  
→ Damage Processing  
→ State Evaluation  
→ Metrics Collection  
→ Benchmark Report Generation

---

## Problems Encountered

The main implementation challenge involved exposing the destruction component's current state to external systems. A public accessor function was required so that the destruction manager could evaluate object outcomes after each damage event.  
  
Several compilation errors occurred during implementation because the new GetCurrentState() function was initially declared and implemented in the wrong class. After relocating the declaration to MVCDDestructionComponent and implementing it correctly, the manager was able to access destruction state information.  
  
Additional compile errors occurred due to Unreal Header Tool include ordering requirements and incorrect header modifications. These issues were resolved by restoring the correct Unreal class structure and rebuilding the project.  
  
Runtime validation confirmed that metrics were correctly collected across multiple destructible object variants and that benchmark reports accurately reflected destruction results.

---

## Solutions / Decisions

A dedicated metrics structure was introduced instead of storing independent variables throughout the framework. This centralises benchmark information and simplifies future expansion.  
  
Metrics collection was placed inside the destruction manager rather than the destruction component. This keeps the destruction component focused on object behaviour while allowing the manager to coordinate framework-wide analytics.  
  
Benchmark reporting was implemented as a separate reporting function capable of summarising destruction statistics after automated tests complete. This design supports future benchmarking, experimentation and dissertation evaluation without modifying the destruction pipeline.  
  
The resulting architecture separates destruction execution, reaction systems and analytics into independent framework layers, improving maintainability and scalability.
